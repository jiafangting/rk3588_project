# rk3588 C 主进程

这是 RK3588 端 C 语言主控工程的说明文档。
它的目标是把“传感器数据、视觉状态、报警决策、报警执行、线程健康检查”串起来。

> 说明
>
> 这一层可以理解成“RK3588 端的大脑”：它不直接做人机界面，也不直接做人脸/目标识别，而是负责协调各线程、融合各来源状态，并决定是否报警。

## 这个目录做什么

这个目录里的程序是 RK3588 端的核心控制程序。它负责：

- 读取传感器数据；
- 查询视觉模块状态；
- 判断是否报警；
- 执行报警动作；
- 监控线程健康状态；
- 管理全局共享状态。

## 文件结构说明

- `main.c`：主入口，启动所有线程并负责统一退出；
- `thread_sensor.c`：传感器线程，负责模拟或读取 STM32 数据；
- `thread_vision.c`：视觉状态查询线程，向 Python 视觉模块请求状态；
- `thread_decision.c`：决策线程，做传感器和视觉的融合报警判断；
- `thread_alarm.c`：报警执行线程，负责真正下发报警动作；
- `thread_heartbeat.c`：心跳线程，检查其他线程是否正常运行；
- `threshold_config.c/.h`：阈值配置读取模块；
- `system_state.h`：共享状态结构体定义。

## 入口与运行流程

程序入口是 `main.c` 的 `main()`。

运行顺序大致如下：

1. 初始化共享状态；
2. 读取阈值配置；
3. 注册退出信号；
4. 启动多个线程；
5. 线程并行运行；
6. 收到 Ctrl+C 后统一退出；
7. 释放资源。

**流程解释**

- 初始化共享状态是为了让各线程一开始就有稳定的数据容器；
- 读取阈值配置是为了让报警判断有依据；
- 注册退出信号是为了让程序能正常收尾，而不是直接崩掉；
- 启动线程后，各线程并行执行各自任务。

## 关键参数和默认行为

### 视觉 socket 路径

- 默认值：`/tmp/vision_inspection.sock`
- 作用：RK3588 端和 Python 视觉模块通信的统一路径
- 可修改方式：设置环境变量 `VISION_SOCKET_PATH`
- 注意：RK3588、UI、语音模块要保持一致，否则会出现“视觉离线”的假象

**说明**

- 这个路径本质上是一个“进程间通信地址”；
- 路径不一致时，程序可能还在运行，但彼此看不到对方。

### 阈值配置

阈值通常从 `config.json` 读取，主要包括：

- `temp_max`：环境温度上限；
- `humidity_min`：湿度下限；
- `humidity_max`：湿度上限；
- `current_max`：电流上限；
- `temp_device_max`：设备温度上限；
- `smoke_alarm`：是否启用烟雾报警。

**说明**

- 这些参数会直接影响 `thread_decision.c` 中的报警判断结果；
- 修改阈值后，报警结果可能会立刻变化。

### 线程检查参数

- 心跳检查周期：通常是 10 秒左右；
- 线程超时阈值：超过 30 秒未更新则视为异常；
- 决策线程轮询：通常是 500ms 一次；
- 传感器线程和视觉线程也都按固定间隔轮询。

**注意**

- 这些参数是为了平衡“实时性”和“资源占用”；
- 太快会增加 CPU 占用，太慢会降低报警响应速度。

## 编译

```bash
make
```

### 作用

编译当前目录下的 C 代码，生成可执行程序。

### 使用场景

- 修改了 C 文件之后重新构建；
- 需要验证线程逻辑是否能编译通过；
- 需要在 RK3588 真机上运行之前先检查语法。

### 前置条件

- 已安装 C 编译器；
- 已安装 `make`；
- 当前目录下存在对应的 Makefile。

### 注意事项

- 如果阈值结构或线程声明改了，记得一起检查头文件；
- 如果涉及 socket 路径，也要检查 Python 端是否一致。

## 运行

```bash
./inspection
```

### 作用

启动 RK3588 主进程。

### 使用场景

- 在真机上运行；
- 在 Linux 环境验证线程协作；
- 与 Python 视觉模块联动测试。

### 前置条件

- 可执行文件已经成功生成；
- 视觉模块已经启动；
- 如果用到串口，硬件接口和权限已经准备好。

### 注意事项

- 如果视觉模块没启动，视觉线程会显示 `UNKNOWN`；
- 如果串口没接入，传感器线程可能会使用模拟数据；
- 退出时建议用 Ctrl+C 正常结束，不要强杀进程。

## 说明

- 串口未接入时，传感器线程会自动切换模拟模式；
- 视觉模块默认通过 Unix Socket `/tmp/vision_inspection.sock` 查询状态；
- 目前报警动作部分已预留 STM32 串口指令接口，后续可以直接接硬件。

## 新手阅读建议

建议按这个顺序看：

1. `system_state.h`：先看共享状态里有哪些字段；
2. `threshold_config.h/.c`：再看阈值怎么读；
3. `main.c`：看整个程序怎么启动线程；
4. `thread_sensor.c`：看传感器数据怎么来；
5. `thread_vision.c`：看视觉状态怎么查；
6. `thread_decision.c`：看报警是怎么判的；
7. `thread_alarm.c`：看报警动作怎么执行；
8. `thread_heartbeat.c`：看健康检查怎么做。
